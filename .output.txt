### IntelliJ Platform Plugin SDK Help

# Dependencies Extension

See [IntelliJ Platform Gradle Plugin – FAQ](tools-intellij-platform-gradle-plugin-faq.html) and [Migrating from Gradle IntelliJ Plugin (1.x)](tools-intellij-platform-gradle-plugin-migration.html).

IntelliJ Platform Gradle Plugin enhances the `dependencies {}` configuration block by applying a nested `dependencies.intellijPlatform {}` extension.

`dependencies {}`
`dependencies.intellijPlatform {}`

This class provides methods for adding dependencies to different IntelliJ Platform [products](#default-target-platforms) and managing [local](#custom-target-platforms) dependencies.

It also includes methods for adding [plugins](#plugins) (including bundled), [JetBrains Runtime](#java-runtime), as well as [tools](#tools) like IntelliJ Plugin Verifier and Marketplace ZIP Signer.

Corresponding required repositories must be defined in the `repositories {}` section, see [Repositories Extension](tools-intellij-platform-gradle-plugin-repositories-extension.html).

`repositories {}`

Example:

setup Maven Central and [`defaultRepositories()`](tools-intellij-platform-gradle-plugin-repositories-extension.html#default-repositories)

`defaultRepositories()`

target IntelliJ IDEA 2026.1

add dependency on the bundled Java plugin

add IntelliJ Plugin Verifier, Marketplace ZIP Signer CLI, and code instrumentation tools

add JUnit4 test dependency

add Test Framework for testing plugin with JUnit4

## Target Versions

The IntelliJ Platform Gradle Plugin allows for using two types of IntelliJ Platform artifacts for development: installers and multi-OS ZIP archives. Both have advantages and drawbacks, but in the 2.x releases, installers are now the default choice when setting up the project.

### Installers

When declaring a dependency on IntelliJ Platform, the IDE installer is resolved by default. The IntelliJ Platform installer is the IDE final distribution used by end-users for installing and running IDE in their machines. Those artifacts are resolved from JetBrains Download CDN (download.jetbrains.com) or Android Studio CDN.

The listing of all present installers can be resolved with updates XML files for [JetBrains IDEs](https://www.jetbrains.com/updates/updates.xml) and [Android Studio](https://jb.gg/android-studio-releases-list.xml) as well as by executing the [`printProductsReleases`](tools-intellij-platform-gradle-plugin-tasks.html#printProductsReleases) task.

`printProductsReleases`

IntelliJ Platform installers are OS-specific and contain bundled [JetBrains Runtime (JBR)](tools-intellij-platform-gradle-plugin-jetbrains-runtime.html), but are limited to public releases only.

To apply required repositories, use [Default Repositories](tools-intellij-platform-gradle-plugin-repositories-extension.html#default-repositories) or explicit [IntelliJ Platform Installers](tools-intellij-platform-gradle-plugin-repositories-extension.html#intellij-platform-installers) helpers.

### Multi-OS Archives

It is still possible to use Multi-OS ZIP archives resolved from [IntelliJ Maven Repositories](tools-intellij-platform-gradle-plugin-repositories-extension.html#intellij-maven-repositories).

To enable resolving this kind of artifacts, opt-out from the installer dependencies by adding `useInstaller = false` argument to helpers described in [Target Platforms](#target-platforms), like:

`useInstaller = false`

The Multi-OS Archives don't bundle [JetBrains Runtime (JBR)](tools-intellij-platform-gradle-plugin-jetbrains-runtime.html) needed to run the IDE locally, perform testing, and other crucial operations. Therefore, it is required to explicitly add a dependency on JetBrains Runtime (JBR) by adding extra `jetbrainsRuntime()` repository and dependency entries.

`jetbrainsRuntime()`

It is advised to rely on installer releases, but targeting EAP multi-OS archives helps when making sure your plugin will work in the upcoming IDE releases.

To apply required repositories, use [Default Repositories](tools-intellij-platform-gradle-plugin-repositories-extension.html#default-repositories) or explicit [IntelliJ Maven Repositories](tools-intellij-platform-gradle-plugin-repositories-extension.html#intellij-maven-repositories) helpers.

## Code Instrumentation

The code instrumentation process handled with the [`instrumentCode`](tools-intellij-platform-gradle-plugin-tasks.html#instrumentCode) task, requires extra dependencies to work and properly adjust the Java bytecode. There used to be an `instrumentationTools()` convenience helper that applied the required dependencies using defaults; it is now deprecated and calling it is no longer necessary. You can still add and configure the dependencies separately if needed.

`instrumentCode`
`instrumentationTools()`

The `javaCompiler()` helper is applied by default and refers to the tool version close to the currently used IntelliJ Platform.
